## 身份和输入

- 固定应用 `wbapp_t1U4NdF6I0IZdm8LzoMLq6`、数据库 `postgres-lgjvhh7s`、动作 `owned.products.upsert`。
- 签发入口先冻结完整产品字段和预期版本，再核对实际平台会话及微信处理凭证；二者须属于同一微信本人。
- 审核沿用 `beauty-product-review-v1` 唯一字段投影和微信审核裁决，任何待审、违规、故障均不签发。
- 版本是客户端操作意图，不能决定真实数据库版本；新建、更新及旧行版本初始化规则须由实际写入通道定义后才接入。

## 凭证

- HMAC-SHA256 覆盖 `beauty-product-receipt-v1|` 加原始 UTF-8 payload，字段包含本人、固定应用/数据库/动作、审核规则、具体行、逐行预期版本、服务端随机 nonce 和时间。
- 有效期最多 120 秒，且不得超出微信处理会话到期时间；256 KiB 总大小上限先于外部请求检查。
- 审核密钥须独立于微信处理密钥；仅配置在未来签发服务和私有验签端，不写源码、日志、客户端或公开表。
- 原始 payload 字符串必须原样验签，不能先解析重排 JSON 再验签；篡改字段、版本、空格或字节均使原签名失效。

## 冲突、重试和终态

- 真正写入端必须独立取得本人身份，并在同一事务中核对每行版本、消费 nonce、执行增量写入、保存可回读收据；任何版本冲突整批拒绝。
- 验签函数不消费 nonce，因此重复验签不代表可重复写入；数据库防重及原子提交目前尚未实现。
- 同一 nonce 只可代表同一本人和同一 payload；重复已提交请求应返回原收据，不增加版本；不同 payload 复用 nonce 必须拒绝。
- 网络或回读失败属于结果未知，不自动重发写入；保留可编辑原稿及待确认操作，先查原 nonce 收据，再由明确操作继续。
- 审核失败、过期、版本冲突保留原稿；只在等价服务端结果回读后确认同步完成。本候选不涉及删除或过期业务记录。

## 尚未具备的上线条件

- WorkBuddy PostgreSQL 的实际 HMAC/RPC 执行能力、两表版本字段和事务权限尚未取得新回执；不能用通用平台文档推断生产支持。
- 可信写入通道、私有密钥保管、事务收据和版本规则验收通过后，才可准备关闭产品直接 INSERT/UPDATE 旁路；旧记录保留。
- 还需具体数据库变更及后台部署授权；本轮没有执行任何上述云端写入。
